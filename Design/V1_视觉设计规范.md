# 宠物生活 App · V1 暖色毛绒视觉设计规范

> 修订版本：2026-10-12 · 时光多宠筛选与宠物列表分层 / 可供 SwiftUI 研发细化
>
> 需求基线：依据用户提供的《完整产品需求与交互设计说明书》以及《V1 快速上线功能选择与 UI 线框》。后者明确为**尚待确认的 V1 候选方案**；本稿暂按默认勾选的 M01–M13 绘制，不将 O01–O23 视为已选择。图片中所有名称、体重、日期均是**演示数据**。

## 一、方向定位

**温暖陪伴 × 奶油留白 × Q 版毛绒公仔。**

- 图 1 仅借鉴：以宠物为主角的大幅留白、轻卡片、收敛的信息密度、简短记录入口。
- 图 2 是 Q 版美术主参考：柔软蓬松的毛绒毛发、偏大的清亮眼睛、短圆的四肢、物种和品种外形正确、胖瘦明显。
- 不做纯儿童游戏风、重拟物、玻璃霓虹、密集仪表盘；不会用粉橙色覆盖整屏。
- 体重、护理等严肃记录使用中性、客观的表达；不把身体变化自动解释为健康结论。

### 2.3 排版与尺寸

- 字体：SwiftUI 系统字体（中文随系统采用苹方），大字标题 **28–32pt Semibold**；普通标题 **18–20pt Semibold**；正文 **15–17pt Regular**；辅助文本 **12–13pt**，基础字号随 Dynamic Type 放大，不强行固定截断。
- 水平页面内边距：**20pt**；卡片间距 **12pt**；同组控件间距 **8pt**；不同大区段间距 **24pt**。
- 卡片圆角 **20pt**；大宠物舞台圆角 **28pt**；小图标容器 **12–14pt**；主操作按钮圆角 **18–22pt**。
- 图片：宠物主视觉约占首屏可用内容高度 **35%–45%**，根据设备高度自适应；头像裁剪不得切断耳朵、尾巴、四肢。
- 点击热区至少 **44 × 44pt**；重要底部操作避开安全区；不使用必须长按才可进入的功能。
- 阴影用于区分层级，不强加多层光晕：`opacity ≈ 0.04–0.08, blur 12–24pt, y 5–10pt`。

### 2.4 图标与导航

- SF Symbols 优先：`house`, `clock.arrow.circlepath`, `pawprint`, `plus`, `book.closed`, `fork.knife`, `scalemass`, `cross.vial`, `bell`, `square.and.arrow.up`。
- **固定四个主 Tab：`首页 / 时光 / 宠物 / 我的`**，底栏视觉从左到右为 **`首页｜时光｜＋｜宠物｜我的`**。中间 `＋` 是独立创建动作，**不是第五个 Tab**，点击后使用系统底部 Sheet。
- `我的` 是一级 Tab，主要整合外观与字体、通知提醒、可读资料导出、隐私权限、关于等设置功能；`宠物` 的 Tab 根页面**只能是宠物简要列表**，点击单只宠物后进入独立档案详情，完整健康与历史内容再次按功能入口进入。首次创建宠物流程不需要 Tab；二级编辑与详情页默认隐藏 Tab 栏，以返回导航为主。探索效果图如保留了底栏，应以本规范的交互规则为准。
- Q 版形象是主视觉，不用系统 Emoji 替代宠物，也不用多种不同插画风格混用。

### 2.5 底部导航（2026-10-12 最新确认）

**结构：四个主 Tab + 中央全局添加，不增加第五个页面。**

```text
┌────────────────────────────────────────┐
│   ⌂        ◷         ⊕        ♧       ♙ │
│  首页      时光      新增记录    宠物     我的 │
└────────────────────────────────────────┘
```

- **业务 Tab**：`首页`（陪伴/今日概览）、`时光`（时间线/照片墙）、`宠物`（列表/档案/健康）、`我的`（设置中心）。
- **中央操作**：`＋` 不参与 Tab 选中、不会保留“加号页面”的导航状态；触发统一新增记录 Sheet，可选写日记、记喂食、记体重、疫苗/驱虫，预填当前宠物后由用户确认。
- **选中状态**：只为当前主 Tab 着色且可叠加淡色圆角选中底，不用仅颜色区分，应同时保持清晰图标形态和文字。
- **首屏行为**：进入 app 默认首页；在 `我的` 修改设置后返回仍保持 `我的` 选中。打开二级页面时记住所属 Tab，返回后恢复滚动位置与当前宠物。
- **场景归属**：时间线与照片墙均属于 `时光` 且复用同一宠物筛选条件；`宠物` Tab 默认只显示可搜索、可筛选的宠物列表，点卡片进入单宠详情，再进入体重、护理等二级；导出资料与外观管理从 `我的` 进入；提醒列表可从首页待办或我的通知入口访问，不设置独立 Tab。
- **尺寸参考**：Tab 栏（不含安全区）高度建议 **56–64pt**；水平分成 5 个等宽槽位，四个 Tab 分布在 1、2、4、5 位；图标约 **20–22pt**、标签 **10–12pt**；中间 `＋` 圆形直径 **46–52pt**；最小点击区域 **44×44pt**，iPhone 底部安全区使用 safeAreaInset 保留。
- **无障碍**：各 Tab 可单独 VoiceOver 标注并暴露选中态；中间圆按钮标注“新增记录”，响应系统减少动态效果；深浅色 token 随系统切换。

### 3.1 时光：宠物单选 / 多选 / 全部（本轮重点）

- **默认范围**：首次进入「时光」显示`全部宠物`，不直接继承首页正在展示的某一只，避免用户误以为记录缺失；返回时光时保留上次已确认的范围。
- **选择方式**：点击顶端「全部宠物 / 已选 N 只」或筛选图标，打开底部 Sheet；“全部宠物”与逐只勾选**互斥**。点一只为单选，点多只为多选；点“全部”恢复无范围限制。
- **应用约束**：候选集合选到 0 只时禁用「查看结果」，或自动恢复全部，**不能用空选集伪装全部**；点击「完成」才更新展示，点取消 / 下拉退出则撤销本次修改。
- **标签与反馈**：`全部宠物` / `团子` / `已选 2 只`。顶部可以用前 2～3 只的缩略头像辅助识别，但超出后用 `+N` 汇总，不要让筛选横条无限扩展。
- **同一筛选贯穿两个模式**：时间线、照片墙共用 `selectedPetIDs`，切换模式不重置；记录类型、时间范围为补充条件，采用交集逻辑。每条结果仍标明具体宠物，避免混淆。
- **范围与写入分离**：`全部`和`多选`仅影响**浏览过滤**，点中央 `＋` 新建实际记录必须明确选定关联宠物；不能把查看了 2 只宠物理解成自动对两只同时保存一条记录。V1 不因此启用 O12 多宠共同事件。
- **空结果**：说明“所选宠物和时间内没有记录”，保留更改筛选及恢复全部入口；删除 / 归档宠物、名字重复时按稳定 `petId` 处理，不能靠名称筛选。
- **照片墙**：仅显示当前筛选范围内已关联的照片，避免重复展示同一资源；点击进入其原记录 / 详情，返回保留筛选条件和滚动位置。

### 3.2 宠物：列表优先、详情后置（本轮重点）

- **Tab 根页面为列表**：顶部标题「宠物」、搜索按钮与「新增宠物」；下一行是 `全部 / 猫 / 狗` 的分类 Chip。若 V1 实际加入归档状态，才增加`已归档`分类；不要提前展示尚未支持的状态功能。
- **列表单元**：一张小头像或 Q 版缩略图、名字、猫狗/品种、年龄（如已填写）、可选单条“最近记录日期或体重”摘要，以及右箭头。避免把性别、生日、疫苗、驱虫、体重曲线、医疗记录全部塞进同一卡片。
- **搜索范围**：按宠物名称、别名（若已填）和品种快速过滤；搜索与猫狗类别取交集；无结果提供清空条件。列表排序默认由用户排序或创建顺序确定，不隐式按健康事件重排。
- **导航动作**：点击卡片任何主要区域 → `PetDetail(petId)`，二级详情先显示形象和关键资料，再用「基本资料 / 健康记录 / 照片与日记 / 提醒与待办」进入下一级内容；返回仍停留在原筛选的列表位置。
- **层级划分**：宠物列表是“挑选对象”，宠物详情是“认识和管理单只宠物”，体重曲线、疫苗驱虫记录和档案编辑分别进入后续页面；不再直接把一只宠物的完整资料当成「宠物」Tab 首页。
- **多宠约束**：该页不提供多选操作来批量改体重 / 医疗信息；多选只用于时光浏览筛选，不新增复杂宠物小家能力（O03）。

### 3.3 关键 UI 尺寸及状态

- 顶部筛选 Chips 高度 32–36pt，左右内边距 12–14pt；头像筛选单元直径约 32–38pt，文字 12–13pt，单元点击热区 ≥44pt。
- 列表卡片高度建议 86–106pt，内边距 12–16pt，头像 54–64pt；卡片可以加极浅的描边，控制阴影与橘色使用面积。
- `accentAction #A75535`：高优先级的确认、已选态；`accentWash #F8E6DA`：浅色选中背景；`border #EBDDD1`：未选边界；暗色使用前述语义颜色。
- Sheet 建议用 `presentationDetents([.medium, .large])`，支持取消 / 重置 / 完成，不依赖长按。VoiceOver 按钮提示“全部宠物，已选中”“团子，已选中”等；大字模式可换成换行列表，减少动态效果下无非必要过渡。

**页面不等于全部独立开发路由。** 05 与 17 为 Sheet；02 与 12 是同一「时光」根页面的两种展示方式；09 是「宠物」根页面，04 是它的二级详情，03 / 11 进一步深入。

### 3.4 我的：设置项补全及分层（本轮重点）

「我的」不承担单只宠物的详细档案，负责**整个 App 的偏好、提醒、存储、隐私及使用帮助**。首页设计为可滚动的设置目录，详情通过二级页面承载。宠物列表/档案数据从「宠物」 Tab 进入；不把所有开关挤在「我的」根页。

| 首页分组 | 入口 | 进入后的真实内容 | V1 处理 |
| --- | --- | --- | --- |
| 常用功能 | 提醒与待办 | 已创建计划、到期状态、完成与编辑 | **纳入** M11 |
| 常用功能 | 可读资料导出 | 选择宠物、事件类型、日期范围、CSV 文件分享 | **纳入** M13；不承诺全量恢复 |
| 外观与使用 | 外观模式 | 跟随系统 / 浅色 / 深色 | **纳入** 基础外观适配 |
| 外观与使用 | 文字与显示 | 说明并正确响应 Dynamic Type 字体缩放，展示当前系统设置 | **纳入** 基础字体适配；非独立字体引擎 |
| 外观与使用 | 减少动态效果 | 遵循 `accessibilityReduceMotion`，说明已启用的系统状态 | **纳入** 基础无障碍 |
| 数据与隐私 | 本地数据管理 | 查看本地宠物、记录、媒体的演示数量、数据保存说明、导出入口 | **纳入轻量版**；不要当做云端管理后台 |
| 数据与隐私 | 隐私与权限 | 查看相册和通知授权；由 iOS 系统维护的权限提供“前往系统设置” | **纳入** 最小授权说明 |
| 帮助与关于 | 使用帮助与反馈 | 常用操作说明、用户反馈入口，具体反馈渠道待落地 | **建议纳入** 轻量支持页 |
| 帮助与关于 | 关于应用 | 版本号、隐私政策和相关说明 | **建议纳入** 基础信息页 |

**通知设置二级页**：通知授权与 App 内提醒计划是不同层级。页面可展示通知权限状态以及疫苗/驱虫、日常护理计划的入口；关闭系统通知不会删除待办，也不会自动把任务标记完成。具体提醒的日期、重复规则仍从该计划详情修改，不在总设置页创造跨宠物共享医疗数值。

**本地数据管理二级页**：数据概览（宠物数 / 记录数 / 照片数）仅作概览，演示数值不可写死；提供已确认的可读资料导出；对原始媒体保留与预览缓存区别作出解释。若未来需要独立“清理缓存”按钮，应先验证可再生成范围与安全确认，不能无条件清除原始照片和用户记录。

**外观与使用二级页**：支持「跟随系统 / 浅色 / 深色」外观选择，但系统字体缩放、减少动态效果不建议用会与 iOS 冲突的独立开关；默认跟随系统并展示说明，必要时链接系统设置。若 V1 尚未选择 O20（完整多语言），先预留本地化结构，不展示无法实际更换语言的选择页面。

**功能边界**：完整可恢复备份 O16、iCloud 同步 O17、CSV 历史导入 O18、完整多语言 O20、桌面组件 O21、Siri/App Intents O22、账号注册/注销与会员付费等，**均不能仅因为本轮补齐“我的”就自动变成 V1 已选项**；确认范围后才放到可交互界面。现有图示若出现这些高级入口，应视为概念探索而非上线需求。

**导航原则**：「我的」是第四个主 Tab；`＋` 继续位于中央且不占 Tab 选中状态。二级设置使用标准导航返回，返回「我的」时保留滚动位置。列表末尾按内容滚动，不通过缩小文字来挤满屏幕。

## 四、Q 版统一原则

1. **真实猫狗基础结构。** 猫必须有一条尾巴、四肢数量正确，动作变换不产生假腿、第二条尾巴、残留棕色肢体等问题；狗也必须遵守品种的耳朵、吻部及尾部形态。
2. **同一只宠物全场景一致。** 角色的眼睛颜色、毛色/花纹、脸型、耳朵和胖瘦配置在首页、档案、分享中一致。
3. **V1 只落地有限静态配置。** 不依赖 AI 实时生图、不假设 3D 模型、自动品种精确识别或完整动作骨骼编辑；后续可扩展但目前不偷加。
4. **三档体型是外形配置。** 偏瘦/标准/偏胖仅影响 Q 版形象，不用作健康诊断，也不能改变真实体重数据。
5. **适配系统减少动态效果。** 本版主形象可先为静态图；不依赖复杂动画传达信息。

## 五、关键状态与校验

- 空状态：未添加宠物 → 新建第一只；无日记 → 明确给出添加入口；无体重 → 不绘制虚假曲线。
- 反馈：新增成功显示轻量提示；失败保留已填内容；删除需确认并提供安全恢复思路。
- 保存真实记录与创建提醒计划应有明确差异，待办状态不会自动计入历史已完成医疗事件。
- 体重有增有减，颜色必须是中性数据表达，不把「增加」一概渲染为负面健康警告。
- 首页的“当前宠物”与时光的 `selectedPetIDs` **互不强制同步**；时光是浏览范围，快速新增记录需要另外明确关联宠物，不能误记到其他宠物。
- 时光和照片墙共享已确认的筛选范围；宠物列表搜索与类别组合筛选；从单宠详情返回须保留列表筛选和滚动位置。
- 深浅色、系统字体缩放、减少动态效果均属于首版基础质量要求。
- 导出 CSV != 完整备份；V1 不显示未确认的完整数据恢复 / iCloud 多设备同步入口。

## 六、从视觉探索稿收敛的地方

静态示意图是审美参考，**不能将画面里所有小元素自动算作 V1 功能：**

- 首页天气数值属于效果图装饰，M01–M13 未要求天气服务，开发应去掉。
- 写日记页中的定位入口不属于这次候选默认范围，应去掉。
- 某些图采用“轻焦糖背景+白字”，实际实现必须换深焦糖底或深色文字，以满足可读性。
- 生成示意中的演示角色年龄、性别及体重可能跨图不完全一致；真实 App 必须由同一 `petId` 数据源驱动，严禁通过视觉稿硬编码。
- 原四组页面图仍在 `总览图/01..04`，额外新增 `总览图/05_时光筛选与宠物列表.png`；`单页图/` 包含原 16 张及新增 `17_时光宠物筛选.png`。旧 `16_设置.png` 已由完整分组的 `16_我的.png` 替代，并新增 `18_外观与显示.png`、`19_通知与提醒设置.png`、`20_本地数据管理.png` 与 `总览图/06_我的设置结构.png`。底栏始终为四个 Tab 加中央全局 `＋`，二级页以返回为主。

## 七、SwiftUI 实施建议（仅 UI 层）

采用 `TabView` 固定四主页面（首页 / 时光 / 宠物 / 我的），独立浮层按钮触发 `sheet` 快速添加；`时光` 以 `Set<PetID>?`（`nil` 代表全部）保存宠物筛选，并由时间线和照片墙共同订阅；`宠物` 用可搜索/物种筛选的列表作为根页面，通过 `NavigationStack` 导航到 `PetDetail(petId)`；卡片、角色舞台、宠物切换器、记录条目、指标摘要、主要按钮、空状态作为复用组件。颜色由 Assets Catalog 语义颜色统一管理，随 `ColorScheme` 提供深浅方案。记录输入使用系统 `Form` 或分组表单承载，并利用 `Dynamic Type` 和 `accessibilityReduceMotion`。不要为了复刻图片而强设状态栏、设备边框和截图阴影。

## 八、可直接给 Codex 的实现描述

> 根据随附《V1_视觉设计规范.md》与 20 张页面与交互状态示意图，在 SwiftUI iOS 应用中实现一致的暖奶油色宠物生活 UI。**时光 Tab 的时间线与照片墙共享宠物筛选：默认全部，用户可选择一只或多只，全部与多选互斥；取消不应用，确认后筛选保留，新增记录仍需明确指定宠物；宠物 Tab 首屏必须是可搜索/猫狗筛选的简要列表，点击卡片才进入单只宠物档案，完整健康记录按模块继续深入。**严格只做候选默认 M01–M13 的页面，不把 O01–O23 作为已确认。底部主导航固定“首页 / 时光 / 宠物 / 我的”，视觉顺序为“首页｜时光｜＋｜宠物｜我的”；中间独立“＋”弹出快速添加，绝不能把“＋”作为第五个导航页面。“我的”根页使用常用功能/外观与使用/数据与隐私/帮助与关于四组入口，并从二级页分别提供外观模式、跟随系统字体与减少动态效果、通知权限和提醒管理、本地数据概览及可读 CSV 导出；不得把账号、iCloud、完整备份、导入等未选 O 项加入 V1；宠物资料仍在“宠物”页面；首页宠物 Q 版毛绒公仔为第一视觉层，第二层为今日待办、记录数及快捷操作，第三层为近期记录。统一语义颜色、圆角、组件和深浅色；主按钮使用满足白字对比度的深焦糖色 #A75535，浅橘 #D58C67 仅用于图表和装饰。首版 Q 版形象只做基础静态猫狗模板、常见毛色花纹和三档胖瘦，不依赖 AI 生图、不实现复杂动作。日记、喂食、体重、疫苗/驱虫、待办必须在信息架构中可达，体重趋势与实际事件分开，严格区分历史已完成记录和待办计划；可读导出只包含选择的记录，不等同于完整备份。去除效果图中的天气、地理定位与其他未勾选功能。使用系统字号缩放、深浅色、减少动态效果，所有关键按钮至少 44pt 点击热区，避免表单输入/导航返回丢失内容。
