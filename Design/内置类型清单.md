一、类型体系是怎么运转的
--------------------------------------------------
App 里 6 个功能共用一个"类型池"，每个功能用不同的编号（type）拉自己的列表：
  type=1 → 提醒事项用     type=2 → 记账用
  type=3 → 异常/体征记录用 type=4 → 日常记事用
  type=5 → 囤货管理用
每个列表末尾都带一个"自定义"项，点它可以添加自己的类型。

附：字段含义速查
--------------------------------------------------
  id        → 类型的服务器编号（程序内部引用用，人不需要记）
  name      → 简体中文名（App 默认显示这个）
  nameft    → 繁体名（繁体语言环境下显示）
  nameen    → 英文名（英文环境显示）
  icon      → 类型小图标图片（存在阿里云 OSS 上）
  note      → 备注（服务器全部留空）
  rank      → 排序值：数字越大越靠前。提醒类 63~99；
              记账/异常类递减；记事和囤货全部为 0（按后台顺序）
  default_repeat_type → 只有提醒类有：选这个类型建提醒时，
              重复周期自动帮你选好（0=从不 1=每天 2=每月 3=每年 4=每周）
              目前服务器全部配成"每天"
  default_frequency    → 配套的重复频率，目前全部为 1
  icon_id   → 图标编号，全部为 0（实际用 icon 网址显示）
  is_user_add → 是否用户自己加的（0=官方内置）
  is_use    → 是否启用（1=启用）。App 只显示启用的

原始完整数据（含图标网址）在 alarm-types.json
