# 喵日记 · Meow Diary

根据 `Design/` 中的视觉稿与类型清单实现的移动端前端原型。React 19 + Vite 6，纯前端，无服务器、账号或云同步。

## 运行

```powershell
npm install
npm run dev
```

打开 http://127.0.0.1:5173 。页面铺满浏览器可用空间，手机使用单列布局，平板和桌面按可用宽度展示多列内容。

```powershell
npm run build
npm run preview
npm test
npm run check:types
```

生产构建在 `dist/` 中，可部署至任意静态 HTTP 服务器。不要直接双击 `index.html`，它需要通过 HTTP 加载模块。

## 已实现

- 首页、时光、猫咪、我的四个 Tab；中央「＋」为独立创建入口。
- 记事 85 项、提醒 25 项、记账 50 项、体征 20 项、囤货 3 项；均从原文自动提取，保留原顺序及重名项。每组支持搜索和自定义名称、图标。
- 日记、喂食、体重、护理及五组类型对应的新增、查看、编辑、删除流程；表单校验和未保存退出确认。
- 多宠物、类型、日期、排序与文本组合筛选；时间线和照片墙共享筛选。
- 猫咪搜索、首次建档引导、照片上传与裁剪、静态形象毛色与体型配置。
- 体重曲线、历史记录、护理记录、独立待办计划、周期提醒。
- 浅色 / 深色 / 跟随系统；响应系统减少动态效果设置。
- 按宠物、类别和日期导出 UTF-8 CSV；下载宠物 PNG 分享卡片。
- 本地存储概览、权限说明、帮助、空状态和存储失败反馈。

首次使用从空档案开始，自动展示猫咪建档引导，不再预填演示宠物。已有本地档案、记录和设置继续保留。用户数据通过浏览器 `localStorage` 保存，存储键为 `meow-diary-v1`。图片在浏览器中压缩后保存，存储失败不会清空表单。清除站点数据会删除本地资料；CSV 不包含照片原件，也不是可恢复备份。

## 猫咪建档

按 `Design/单页图/21_猫咪建档_开始.png` 至 `33_猫咪建档_保存失败.png` 实现全部 13 个页面与状态：入口 → 基本资料 → 纪念日 → 健康资料 → 档案确认 → 完成；包含头像、照片裁剪、品种与日期选择，以及名字校验、退出确认、保存失败重试。

- 只有名字必填。品种、性别、生日、到家日、绝育状态和体重都可稍后补充；设计图里的示例资料不是默认值。
- 六种猫咪头像；上传照片可拖动、缩放、旋转和重置，确认后保存实际裁剪结果。
- 日期选择支持触摸滚动、点击与键盘方向键，限制未来日期并校验到家日不早于生日。
- 创建档案和第一笔体重记录一起写入本地存储。保存失败保留输入，重试不会重复建档。
- 完成后可进入首页或继续添加猫咪；“猫咪”页和首页切换面板的添加入口复用同一流程。
- 未保存退出会确认；刷新或关闭页面也会触发浏览器的离开提醒。

已有档案时，可访问 `http://127.0.0.1:5173/?onboarding=1` 查看完整引导。这个入口保留已有数据，创建的新猫咪会追加保存；完成后移除 URL 中的预览参数。

通知是浏览器能力，仅在用户授权且页面打开时检查，不具备后台推送能力。未加入登录、云端同步、真实定位或天气服务。

## 设计与素材

原始设计保存在 `Design/`，未修改。前端实现与原稿中的 SwiftUI 技术建议分开，以用户要求的 Web 前端为准。中央「＋」按用户指定的完整类型清单扩展。

当前界面采用 `Design/风格探索/home-photo-sticker-v2.png` 确认稿的白底、手绘描边、彩色贴纸与便签风格。首页可点按宠物互动，也可直接勾选待办；时光、照片墙、宠物档案、表单和设置复用统一样式。

猫咪使用照片质感透明抠图，白边和轻投影通过本地 SVG filter 显示。常用图标使用透明贴纸图集，其他图标使用 Lucide。素材与完整提示词见 `ASSETS.md`。图片均为本地资源，运行时没有生图或远程素材请求。既有本地资料中的猫咪路径会自动映射到新版素材，无需重置数据。

## 验证

`npm test` 覆盖多条件交集、空选集、排序、日期边界、照片范围、CSV 转义与公式注入防护，以及计划与实际记录分离、周期待办补排与去重、一次性待办撤销。

`npm run check:types` 将生成的 `src/types.json` 与原始类型清单逐项比较。更新原始清单后，可运行 `node scripts/import-types.mjs` 重新生成。

`tests/catProfile.test.mjs` 覆盖首次启动、既有资料保留、选填资料校验、建档与体重的原子保存、重试去重及裁剪边界。`tests/onboarding.browser.mjs` 使用隔离的 Playwright 浏览器上下文走通 13 个状态、照片上传裁剪、保存失败重试、连续建档和 5 种屏幕尺寸；不会操作用户浏览器中的资料。启动 Vite 后，确保 Playwright 可通过 `NODE_PATH` 找到，运行 `node tests/onboarding.browser.mjs`。默认使用已安装的 Edge，可通过 `BROWSER_CHANNEL` 改为其他 Chromium 通道。验收截图位于 `qa/screenshots/cat-*.png`。

浏览器验收页 `http://127.0.0.1:5173/qa/mobile.html` 同时展示 375px 与 320px 的窄屏布局。
响应式验收页 `http://127.0.0.1:5173/qa/responsive.html` 可切换 320px、375px、768px、1280px 和横屏视口，并检查页面是否铺满及有无横向溢出。
